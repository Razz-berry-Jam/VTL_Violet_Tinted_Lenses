# VTL_Violet_Tinted_Lenses
Utalising cold war technology and cryptography for improved encryption methods between parties. "Punching" messages into images and videos generated by a polymorphic cypher. WIP - can encode and decode within a docker, punching into the image/video is not yet complete.

# Setup: 

Make sure you have docker installed  
docker --version  
if there is no response, docker is not installed you will need to download it for yourself 
once it is installed  
in the directory as the Dockerfile run the command 
docker build -t vtl .  
sudo docker run vtl --help  
you should then be able to run the program 

# Command examples: 

sudo docker run vtl encode --help will display the help menu for the encode function 

sudo docker run vtl decode --help will display the help menu for the decode function 

sudo docker run vtl encode X.txt Y.txt Z.mp4 will run the encode function taking:  
the contents of X as the secret message  
the contents of Y as the key  
Z as the mp4 to encode the message onto 

sudo docker run vtl decode X.txt Y.mp4 Z.txt will run the decode function taking:  
the contents of X as the key  
the contents of Y as the as the unaltered video  
Z as the txt congaing the output of the encode function  
ideally it would be the mp4 to decode the message from  

sudo docker run vtl Fialka_info This will output information about Fialka from wikipedia for you to read. 


# User notes: 

If you want to test yourself in the current state here is how!  
It is not fully finctional I am afraid, it extracts the frames into annexB but not decompressed. 

The encryption functions work just fine!  
The frame extraction only happens when you run encrypt mode so you will see the annexB data [very long]  
Encryption will also produce a output in the CLI displaying the encrypted text. 
It uses the key named valid_test_key.txt but feel free to make your own. 
Modify the contents of the valid_test_key, make a 30*30 grid with only one 0 in each column and row.  
The key is stored in test_message the key can be anything within the charcter set: a-z '.' ' ' '?' '!' 

In decode mode you will need to pass the output.txt file in instead of the encoded video. 
 This file must contain the output of your encryption,  
if the last charcter was a space ' ' or [31] you will need to include it in the output file.  
By default it already has the output of the test message ready to go for you to test.  
If you want to try it yourself, take your output, place it into output.txt, and rebuild the docker.  
Fun fact there is also a third mode!  
Replicating the base machine there is a plain text mode, why?  
Testing, and maybe if you were desperate for a typewriter.  
As the project has not been declassified, we cannot say for certain.  
It cannot be triggered in the docker, this was just added to be faithful to the original machine.
